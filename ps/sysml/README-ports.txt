PowerShell ports of the SysML v2 text tools and the IDEF0 toolkit (job H3)
=========================================================================

Windows PowerShell 5.1, Constrained Language Mode safe, pure ASCII scripts. Every command was compared with the
Perl original on the same input: stdout bytes, stderr text, exit status, and every generated file (diff -r).

  ps\idef0\idef0.ps1          tools/idef0/idef0.pl        lint text html svg dump links fmt [--number|--auto] [--write]
  ps\idef0\idef0-backlog.ps1  sim/idef0-backlog.pl        MODEL.md [--date D] [--sprint N] [--people N] [--cap N --commit] | --roster
  ps\sysml\sysml.ps1          tools/sysml/sysml.pl        check corpus tokens grammar (crosscheck: needs Java, not run)
  ps\sysml\model.ps1          tools/sysml/model.pl        help check stats nouns verbs docs idef0 trace tags new rename lint
                                                          backlog precommit libnames validate install-hooks
  ps\sysml\sysml-lib.ps1      tools/sysml/lib/SysML       grammar loader, lexer, recognizer (dot-sourced by the two above)
  ps\sysml\grammar\           the published KerML / SysML v2 KEBNF + the kit's errata, and sysml.cache (prebuilt)
  ps\sysml\sysml-library-names.txt   library names lint resolves against (model.ps1 libnames refreshes it)

Run:  powershell -ExecutionPolicy Bypass -File ps\sysml\model.ps1 --root C:\work\halberd lint
      (or the .cmd launchers beside each script).  --out FILE (all four tools): write stdout to FILE as UTF-8
      without a BOM. Use it instead of '>': Windows PowerShell 5.1's '>' writes UTF-16, which browsers, Word and
      the other tools do not expect.

What is the same
- Output, exit codes and generated files byte for byte, including docs/Nouns.md, Verbs.md, Traceability.md,
  docs/idef0/<name>.md, plates.html, INTERFACES and svg/*.svg. The generated headers still say
  "Generated by: perl tools/sysml/model.pl ..." on purpose: a team can mix the Perl and PowerShell tools on one
  model, and neither will think the other's docs are stale.

What differs, and why
- validate    needs Java and the OMG SysML v2 Pilot. The port prints model.pl's "skipped" text plus one line:
              not run. Not run is not green: the model has not been through the reference parser. Exit 3.
- precommit   no git: instead of comparing with the git index, it snapshots docs/, regenerates, and lists the
              files that changed (same "out of date" verdict and exit status).
- install-hooks  needs git: refused with a message, exit 1.
- draw, plates, diff, threats, gate   the views toolkit, ported in views\*.ps1 (draw tree|trace|ibd|pkg, plates
              [--auto], diff OLD_DIR [NEW_DIR], threats, gate [--strict] [--svg]); byte-identical to Perl. diff --git
              needs git: refused with exit 2 (export the two versions to folders and compare those). 10-60 s each.
- crosscheck  (sysml.ps1) needs Java: prints the Perl's own "needs Java" message, exit 3.
- corpus      (sysml.ps1) prints timings, so it can never be byte-identical; the per-file results are.
- libnames    writes ps\sysml\sysml-library-names.txt (the file the port reads) and names that path.

Limits to keep honest
- sysml.ps1 check and model.ps1 lint are a syntax and convention checker generated from the published grammar, NOT
  the reference parser. They do not resolve names, imports or types the way the standard does. The Halberd
  phase-2 baseline passes both (Perl and PowerShell agree) and fails the OMG Pilot with 47 errors and 5 warnings:
  missing imports, a subject that is not the first parameter, and 'Threat' resolving to the wrong package.
  A green lint here is not evidence of valid SysML v2.
- Speed (Constrained Language Mode makes every PowerShell call ~75 us): the grammar recognizer parses about
  50-70 tokens a second, so a first lint of a 30-file model takes minutes. Results are cached per file
  (path, size, write time, grammar) in %TEMP%\agile-sysml-check2.cache: re-running lint after editing one file
  re-parses only that file. sysml.cache beside the grammar saves ~20 s of grammar loading per run; it is rebuilt
  automatically if a grammar file changes.
- stats "longest chain": when two chains tie, Perl picks the first in hash order (random per run); the port
  picks the first in name order. Depths and counts are the same.

Gotchas found while porting (for anyone extending these files)
- PowerShell variable names are case-insensitive ($L and $l are one variable); scripts keep them distinct.
- 'R' is the alias of Invoke-History and '$pid' is read-only: names are chosen to avoid both.
- A function that returns an empty array with ', @()' counts as 1 inside @(...): call sites use the value directly.
- In an array literal ',' binds tighter than '+': concatenations inside @(...) are parenthesised.
- [Math], [object]::Equals, Get-FileHash, Compress-Archive, ArrayList and generic List are refused in CLM.
