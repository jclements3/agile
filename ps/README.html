agile.ps1 — the agile kit on a locked-down DoD laptop

The kit's daily loop in Windows PowerShell 5.1. It needs no install, no compiler, no admin rights, no network, and no Git for Windows. It runs under Constrained Language Mode (AppLocker/WDAC). It reads and writes the same files as the Perl kit (scrum.conf, scrum.txt, standups\), so either one can work on the same project folder.

1. Put it on the laptop

Copy agile.ps1 and agile.cmd into one folder, for example Documents\agile, then make a project:

cd Documents\agile
.\agile.cmd init townhall
cd townhall
..\agile.cmd status

Edit townhall\scrum.conf in Notepad. Set facilitator to your Teams display name, so your own chat lines aren't linted. Set banner and the marking lines if the material is marked; they then go on every report and on the workbook's print header.

If agile.cmd is blocked, start it directly:

powershell -NoProfile -ExecutionPolicy Bypass -File ..\agile.ps1 status

If Group Policy forbids .ps1 files entirely ("running scripts is disabled"), load the text instead of the file. Paste this once per PowerShell window, then type agile status, agile paste Alpha, and so on:

function agile { Invoke-Expression ('& {' + (Get-Content -Raw "$HOME\Documents\agile\agile.ps1") + "`n} " + ($args -join ' ')) }

In that mode, put quotes inside the quotes for arguments with spaces, for example agile paste "'Team A'".

2. Every morning in Teams

StepYou doCommand
1Post your usual prompt; people answer Y: ... T: ... B: ... with task ids
2In the Teams chat, click the message list, then Ctrl+A, Ctrl+Cagile paste Alpha
(saves standups\<today>-Alpha-chat.txt and lints it)
3Paste the replies back into the chat (Ctrl+V): the people whose status could not be read, or who named an unknown taskagile lint -Reply -Clip
4After corrections, copy the chat again and re-run step 2
5Record the answers; flags and suggested lines go into today's stand-up fileagile answers (add -Assume for the silent)
6Open standups\<today>.txt in Notepad. Uncomment the suggested done/block lines you agree with, and add your ownnotepad standups\2026-10-14.txt
7Apply it to the journalagile compile
8Reports and the spreadsheetagile report

One chat for several teams works too: agile paste with no team name splits the answers by each person's team in the journal.

If paste says "no messages recognised", Teams copied the chat in a layout the parser doesn't know. Open the saved -chat.txt file and look at how a message header looks. The parser accepts [9:05 AM] Name, Name 9:05 AM, 9:05 AM Name and Name: text.

3. The stand-up file (what compile reads)

2026-10-14
sprint 7
== Alpha
done ABC-2
new ABC-4 5 Export to Excel p:1 e:Reporting o:"Lee, Ann"
commit ABC-4 Lee, Ann
block ABC-3 waiting on ISSM approval
est ABC-5 8
cap 30
note Bob out Friday

The verbs are done carry drop commit refine prune new new! est assign block unblock hold resume punt redo pass sync cap note risk absent. A file with any error is refused whole and every error is listed, so the journal never takes half a day.

4. The spreadsheet, metrics and reports

agile report writes these to reports\:

  • backlog.xml, an Excel workbook. Double-click it, or use Excel's File → Open. It has a Summary sheet (sprint status, the team table with done %, load %, average velocity and blocked count, and the blocker list), plus Backlog, Sprints, Epics and Intake sheets. Every sheet has a filter on the header row, the header frozen, numbers as numbers and dates as dates. It is rebuilt every run, so close it in Excel before running report.
  • items.csv sprints.csv epics.csv intake.csv, for your own workbook. Load each one once with Data → Get Data → From File → From Text/CSV → Load. After that, Data → Refresh All picks up each day's numbers, and any charts or PivotTables built on them refresh too.
  • <date>-status.html, the status page. Open it in Edge to read it, print it to PDF, or select all and paste it into an Outlook mail. <date>-status.txt is the same as plain text.
  • <date>-brief.txt, the BLUF leadership note: RED/AMBER/GREEN, one sentence and at most five bullets.

To check numbers at the console, use agile sprint, velocity, backlog Alpha, members, epics, roadmap or blocked.

5. How it was checked

Every test ran with PowerShell forced into Constrained Language Mode. Outputs were compared byte for byte with the Perl kit:

  • All read commands on the demo (241 tasks, 10 teams), Halberd and a verb-coverage project: 63 commands, identical.
  • Every stand-up file recompiled from scratch: 66 compiles, identical journals and identical refusals.
  • Chat lint in every mode, plus answers, flags, attendance and suggested lines, on rehearsal chats with seeded mistakes and on about 4,800 fuzzed messages: identical.
  • The CSVs, the status text and the brief: identical. The HTML page and the workbook are new in this version and were checked by rendering and opening them.

Windows PowerShell 5.1 itself couldn't run here. The script was scanned for anything newer than 5.1, and the language-mode rules are the same in both.

6. Differences from the Perl kit

  • Not ported: Outlook drafts and invites (COM is blocked in this mode), the health thresholds (Metrics.pm), the cockpit dashboard, the quad, the memory drill, the AI step, #est/#vote tallies, and the Vim integration. Notepad is the editor.
  • Fixed rather than copied: en/em-dash labels (Today – ...) and the 👍/✅ answers now work. Answers.pm lacks use utf8, so Perl misses them and reads "B: 👍" as a blocker.
  • Deterministic: Perl's members and the example ids in lint -Reply change from run to run (hash order). This version always orders by priority, then created date, then id.
  • Case: team, task and owner names are matched without regard to case (Alpha = alpha). People in the chat are matched exactly, as in Perl.
  • Files written by Windows PowerShell 5.1 start with a UTF-8 byte-order mark. Both kits ignore it.
