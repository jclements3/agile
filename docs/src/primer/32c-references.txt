== References: DoW and Microsoft guidance {#references}

::: bridge
You know: the applicable documents list at the front of a SEMP, with each document's number and where to get it.

Here it is called: references: the Department of War's software and DevSecOps guidance and Microsoft's Azure Government pages.

What is new: these documents are written for software teams; this appendix says which part a systems engineer needs.
:::

[[reading]] lists titles only, because web addresses move. This appendix makes one exception: the official
Department of War (DoW, formerly DoD) and Microsoft pages a program office will ask about, with the addresses as the
DoW CIO library linked them on 3 October 2026. Start from the two index pages (the DoW CIO library and Microsoft's
Azure Government documentation); when an address below has moved, the document is still listed there under the same
title. Check with your security office before downloading anything to a work laptop.

The kit also carries a condensed guide to these documents, `docs/ModernSoftwarePractices.pdf` (*Modern Software
Practices: A Condensed Guide*, about 35 pages): what each one is, whether it is policy, guidance or a draft, its key
points with page references, and what it means for a small model team. It is unofficial; the originals govern.

=== DoW software and DevSecOps guidance {#references-dod}

The DoW Chief Information Officer (CIO) library groups the documents under five headings: modern software practices,
the DevSecOps document set, the reference designs, open source software, and continuous authority to operate. The
titles below are the library's. All are approved for public release except where noted.

|| Document | What to read it for ||
| **DoW CIO Library** (the index) `https://dodcio.defense.gov/library/` | the current versions of everything in this section; start here |
| **DoWI 8430.01, Accelerated Mission Software** (effective 8 September 2026) `https://www.esd.whs.mil/Portals/54/Documents/DD/issuances/dodi/843001p.pdf` | the instruction: modern practices, pipelines as critical infrastructure, SBOMs and machine-readable evidence, value-stream measures, rules for AI-generated code. The one document here that is policy for every program |
| **DoW Software Modernization Strategy** `https://dodcio.defense.gov/Portals/0/Documents/Library/SoftwareModStrat.pdf` | the department-level goals [[directive]] cites: cloud, software factories, continuous authorization |
| **DoW Software Modernization Implementation Plan Summary for FY25-26** `https://dodcio.defense.gov/Portals/0/Documents/Library/SW-Mod-I-Plan25-26.pdf` | the tasks behind the strategy, for the program manager |
| **DoW Enterprise DevSecOps Fundamentals** `https://dodcio.defense.gov/Portals/0/Documents/Library/DoD%20Enterprise%20DevSecOps%20Fundamentals%20v2.5.pdf` | the definitions: the ten-phase lifecycle, the software factory, culture and metrics. The vocabulary management will use; compare it with [[devsecops]] |
| **DoW Enterprise DevSecOps Activities & Tools Guidebook** `https://dodcio.defense.gov/Portals/0/Documents/Library/DevSecOpsActivitesToolsGuidebook.pdf` and its workbook `https://dodcio.defense.gov/Portals/0/Documents/Library/DevSecOpsActivitesToolsGuidebookTables.xlsx` | the activities by phase, REQUIRED or PREFERRED. Map the team's pipeline jobs ([[pipeline]]) onto its tables when an assessor asks "which activities do you perform?" |
| **The State of DevSecOps Report** `https://dodcio.defense.gov/Portals/0/Documents/Library/DevSecOpsStateOf.pdf` | findings and a measurement playbook: "Manage to mission value, not metrics" |
| **DoW Enterprise DevSecOps Reference Design: CNCF Kubernetes** `https://dodcio.defense.gov/Portals/0/Documents/Library/DoD%20Enterprise%20DevSecOps%20Reference%20Design%20-%20CNCF%20Kubernetes%20w-DD1910_cleared_20211022.pdf` | the approved design the platform team follows when the runners run on Kubernetes ([[runners]]) |
| **DRAFT: DOW Cloud IaC + GitHub + Azure** `https://dodcio.defense.gov/Portals/0/Documents/Library/DoDRefDesignCloudGithub.pdf` | a draft design for a cloud-hosted factory on Azure; its runner and credential patterns carry over to other tools |
| **Software Development and Open Source Software Memorandum** `https://dodcio.defense.gov/Portals/0/Documents/Library/SoftwareDev-OpenSource.pdf` | adopt, buy, create; how to assess and release open source |
| **Memo: Continuous Authorization to Operate (cATO)** `https://dodcio.defense.gov/Portals/0/Documents/Library/20220204-cATO-memo-Signed-Cleared.pdf` | the three competencies an authorizing official must show; what the ISSM will ask about ([[security]]) |
| **DevSecOps cATO Evaluation Criteria** `https://dodcio.defense.gov/Portals/0/Documents/Library/cATO-EvaluationCriteria.pdf` | the evidence a cATO request needs: control gates described and demonstrated, SBOMs, training |

The library also holds the DevSecOps Playbook, the Pathway to a Reference Design, the CNCF Multi-Cluster Kubernetes
design, a draft AWS design, the Accelerating Secure Software memo and its RFI summary, and the cATO Implementation
Guide (whose cover is marked Distribution C); the condensed guide covers all of them.

=== Microsoft: Azure Government for DoD {#references-azure}

|| Document | What to read it for ||
| **Department of Defense (DoD) in Azure Government** `https://learn.microsoft.com/en-us/azure/azure-government/documentation-government-overview-dod` | the DoD regions and which impact levels each supports; what "the runners are in Azure" means for where the model may live |
| **Azure Government isolation guidelines for Impact Level 5 workloads** `https://learn.microsoft.com/en-us/azure/azure-government/documentation-government-impact-level-5` | how IL5 workloads are isolated; for the platform team, and for the ISSM conversation in [[security]] |
| **DevSecOps puts security at the heart of program development** (Azure Government blog) `https://devblogs.microsoft.com/azuregov/devsecops-puts-security-at-the-heart-of-program-development/` | a short orientation to Microsoft's DevSecOps offerings for government |

::: tip Which three to read first
For a systems engineer starting the twelve weeks: the **DevSecOps Fundamentals** (the words), the **Activities &
Tools Guidebook** (to map your pipeline), and section 3 of **DoWI 8430.01** (what is now required, and what management
will measure).
Leave the reference designs and the Azure pages to the platform team unless you are asked.
:::
